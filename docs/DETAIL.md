# 本地 LLM 中转站

把多个 OpenAI 兼容上游（公益站、中转站、自建网关）合并成**一个本地出口**，Harness 里只出现一个 provider，而不是一堆站点。

## 为什么需要它

手上有一堆第三方令牌时，每个站点的模型名、可用性、限流策略都不一样。直接配到 Harness 里会有两个后果：设置页越来越长；某个站挂了只能人工发现再切。

这个插件做三件事：

1. **进程托管** —— 网关跑在 DSH 宿主进程内，启用插件即启动、禁用即停止，不额外拉进程。
2. **自动故障转移** —— 同一个模型名在多条通道间依次重试，失败通道进入冷却。
3. **一个工具** —— `llm_gateway` 查看通道健康度、启停、热加载。

## 工作方式

```
Harness  ──►  http://127.0.0.1:4000/v1  ──►  ch1 ─┐
                                          ├─►  ch2 ─┼─► 上游站点
                                          └─►  chN ─┘
```

插件不内置任何凭据；你只需提供 `channels.json`（自己的站点与令牌），首次启用时会释放一份 `channels.example.json` 作参考。

## 前提条件

- Node 20+（DSH 本身的要求）。
- `channels.json` 里至少一条可用通道。

## 故障转移判定

| 上游返回 | 行为 |
|---|---|
| `2xx` 且 body 含 `choices`/`data`/`content` | 成功，记录延迟 |
| `2xx` 但 body 是错误信封 | 判失败并换通道 |
| `401` / `403` | 换通道，冷却 30 / 15 分钟 |
| `429` / `5xx` / 超时 | 换通道，冷却 2 分钟 |
| 其它 `4xx` | 直接返回 |

## 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 插件挂载时是否自动启动 |
| `host` | `127.0.0.1` | 监听地址 |
| `port` | `4000` | 监听端口 |
| `dir` | 空 | 工作目录；空表示 `<用户主目录>/.dsh/llm-gateway` |

## 安全边界

- 默认只监听回环地址，入口另有 Bearer key（首次启动生成，写入 `gateway.json`）。
- 不读取、不上传 `channels.json`；日志只落本地 `logs/requests.ndjson`。

## 已知限制

- 只代理 `/v1/chat/completions` 与 `/v1/models`，不转发 embeddings / images / Anthropic 原生 `/v1/messages`。
- 上游可用性不由本插件保证，它只负责"挂了自动换下一个"。
